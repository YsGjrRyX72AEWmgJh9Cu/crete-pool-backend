# Hellenic American Pool History Platform

# Constitution

Version 1.0

---

# Mission

The Hellenic American Pool History Platform exists to preserve, organize and present the history of American Pool in Greece.

It is more than a software project.

It is a long-term effort to build a reliable historical archive for players, tournaments, clubs, organizers and future generations.

Every technical decision should support that mission.

---

# Our Philosophy

> As clean, clear, simple and reliable as possible.
>
> Creative.
> Flexible.
> Autonomous.
> Timeless.

These are not goals.

They are requirements.

---

# Our Principles

## 1. Simplicity

Prefer the simplest correct solution.

Complexity must always be justified.

---

## 2. Clarity

Code should be easy to read.

Names should explain themselves.

Every file should have one responsibility.

---

## 3. Reliability

The project should always remain in a working state.

Before every commit:

- Tests pass
- Documentation is updated
- Git history remains clean

---

## 4. Domain First

The Domain Model belongs to this platform.

External systems never define our architecture.

---

## 5. API First

Whenever an official API exists, use it.

HTML parsing is the last option, not the first.

---

## 6. Independence

CueScore is a source of data.

It is not our platform.

The historical archive must remain independent.

---

## 7. Evolution

The architecture must support future growth.

New features should extend the system instead of forcing major rewrites.

---

## 8. Documentation

Documentation is part of the project.

If the code changes, the documentation changes.

---

## 9. Truth over Assumptions

Never assume.

Research.

Verify.

Implement.

---

## 10. Respect the Sport

Every player.

Every match.

Every tournament.

Every referee.

Every club.

Every organizer.

Every volunteer.

Every contribution matters.

This platform exists to preserve the history of American Pool in Greece with accuracy, objectivity and respect.

The goal is not simply to collect data.

The goal is to preserve the people and the stories behind the data.

---

## 11. Continuous Improvement

Every Sprint should improve the project.

Not only by adding features.

But by making the architecture cleaner.

The code simpler.

The documentation clearer.

And the platform more maintainable.

---

## 12. Legacy

This project is built for future generations.

Technology will change.

Frameworks will change.

Programming languages will change.

History must remain.

Every design decision should help preserve that history for decades to come.

# Motto

Quality before speed.

Clarity before cleverness.

# Decision Rule

Whenever there are multiple possible solutions, choose the one that is:

- Cleaner
- Simpler
- Easier to understand
- Easier to maintain
- More independent
- More timeless

Never choose complexity unless it provides a clear long-term benefit.
